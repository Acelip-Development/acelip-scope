# LUCY Diagnose 1.5 packaging validation

Version: **1.5.0-dev**. Branch: **codex/v1.5-packaging**.
Baseline: `ac51ab16d777060209cbe3236e2bb747aa88aab1` (176 passing tests).
Final artifact source: **`2765486a9e610748d241ebb4b8ef0966c6f511d7`**, clean at
build time. The subsequent documentation commit records these results; package
provenance intentionally identifies the actual source commit used for the build.
No push, tag, publication or GitHub Release was performed.

## Result

Both real package formats built, launched and passed packaged GTK acceptance.
Two independent builds of each final format produced **identical bytes**.
SHA-256 manifests were generated, re-read and verified, and compared across the
independent output directories. **217 regression tests plus 4 optional Gio
integration tests passed: 221 total**, retaining all original 176 tests.

This validates the packaging phase within the explicitly bounded environments
below. It does not claim general Linux desktop compatibility or complete
FileChooser/capture acceptance. Successful manual save-picker selection, actual
screen capture, playback and hardware SMART success remain untested.

Machine-readable evidence: [v1.5-execution.json](validation/v1.5-execution.json).
Build/permission/launch instructions: [PACKAGING.md](PACKAGING.md).

## Environment and prerequisites

- Actual host: Ubuntu **26.04.1 LTS**, x86_64, Linux **7.0.0-34-generic**,
  GNOME Wayland desktop; build Python **3.14.4**.
- Existing Flatpak CLI **1.16.6** and GNOME Platform **50**, runtime commit
  `b1935f7a673108616d4fd84564f15cefc9f637481472a8d4d2f0945375d41f4b`.
  Packaged Python is 3.13; GTK, libadwaita, GI and Cairo come from this runtime.
- Existing `mksquashfs` **4.7.5**, zstd, two compression workers.
- Official AppImage type-2 runtime commit
  `75849dce7cc37e4319b633df1f116ca895c71a12`, pinned SHA-256
  `1cc49bcf1e2ccd593c379adb17c9f85a36d619088296504de95b1d06215aebbf`.
  Downloaded into temporary/project tooling storage; no host package installed.
- `flatpak-builder`, GNOME SDK and `appimagetool` were absent. The documented
  pure-Python Flatpak CLI route and pinned type-2-runtime/SquashFS route built
  successfully without them. No fabricated fallback artifact was used.
- Additional environment: existing Fedora **44** container userspace, rootless
  Bubblewrap, image manifest
  `sha256:be9d65e2344d805cc11114319c685ecaa96b6d9b4350a0a6460cdb931babbd19`.
  It shares the Ubuntu compositor socket but has private process/network/device
  namespaces, no host sysfs and no independent session bus/systemd/audio stack.
  No guest packages were installed during this phase.

Flatpak was installed only into `var/v15-flatpak-install` via
`FLATPAK_USER_DIR`; the normal user/system Flatpak installation was not changed.
Flatpak's normal app-private state/QA directory was created under its application
ID. AppImage preferences/cache/state and all additional QA writes were directed
into project `var/`. There were no host package installations, service changes,
privilege escalation, desktop settings changes or configuration repairs.

bundle-generation timestamp. The builder normalizes this unsigned GVariant
field through GLib, preserves every other serialized child and content commit,
and rejects an unknown layout. The normalized final bundle was installed and
run successfully, including full GTK acceptance. AppImage normalization uses
fixed ownership, timestamps and SquashFS parameters. Identical results are
established for the recorded tools and inputs, not all future tool versions.

## Packaged GTK acceptance

Each final artifact's harness verified its module came from the package rather
than a checkout. About and the harness record show the exact clean source SHA,
version, package format, GNOME 50 runtime, Linux backend and correct host-access
context. AppImage was launched from an unrelated working directory and uses
Python safe-path mode.

All three final runs passed:

- Dashboard and all seven modes: Quick Scan, Full Scan, GPU, Network, Storage,
  AI Stack, Discord / Screen Sharing; no collector crashes.
- All **13** built-in themes selected, written to isolated QA preferences,
  flushed, reloaded with a new SettingsStore and reflected in the UI; no CSS
  parser errors. Packaged XDG path selection also has regression coverage.
- Pause/resume, live samples, compact and wide layouts, one application window.
- Existing real UI assertions for privacy filtering, new-finding/provider
  consent reset, and explicit manual screen-sharing cancellation.
- Real Markdown and JSON preview generation followed by real asynchronous Gio
  writes and exact content verification; no synthetic replacement of IO.
- Existing-file confirmation, cancellation preserving original contents,
  confirmed replacement and rejection of a changed etag.
- Invalid/nonexistent parent and unwritable destination errors shown correctly.
- Real Gtk.FileDialog opened and programmatically cancelled without writing.
  **Successful user selection through native/portal FileChooser is NOT TESTED.**
  Direct Gio writes establish saving behavior, not completion of portal grants.

The final acceptance JSON files and corresponding logs are:

- Flatpak: app-private `data/v15-final-qa/validation.json`, copied in full into
  the tracked execution record; `var/v15-flatpak-final-qa.log`.
- Ubuntu AppImage: `var/v15-appimage-final-qa/validation.json`;
  `var/v15-appimage-final-qa.log`.
- Fedora AppImage: `var/v15-fedora-final/qa/validation.json`;
  `var/v15-fedora-final-qa.log`.

An earlier Fedora run exposed an async buffer-lifetime bug in new-file saving.
The corrected writer uses a GBytes-owned memory stream and asynchronous splice.
A dedicated large-Unicode-export regression test stresses garbage collection;
all three final package runs verify actual saved contents. An earlier AppImage
run also exposed its immutable FUSE mount as a false full-disk finding; the final
backend explicitly identifies only its own image mount, preserving other disk
health checks.

Flatpak Full Scan had zero ERROR results from the restrictions; details use
PARTIAL/UNAVAILABLE and explicit sandbox evidence. Readable runtime OS is
labeled GNOME 50 (Flatpak runtime), not Ubuntu host identity. No host filesystem,
raw device, network, system-bus or unrestricted session-bus permissions were
added. FileChooser uses GTK's portal-backed dialog; ScreenCast inspection uses
only a read-only property query with NO_AUTO_START. No capture session or
PipeWire stream was opened.

SMART's five distinctions are covered: missing tool, permission denied,
sandbox-restricted, unsupported device/bridge and successful response. Missing,
unsupported and successful hardware responses are **fixtures** where noted;
actual host SMART reads were permission-denied, and no privileges were changed.
`wpctl` live success was observed; `pactl` fallback remains fixture-tested rather
than claimed as a live fallback run. Missing-tool behavior was also exercised
by the actual reduced Fedora userspace.

## Security and remaining limits

AI analysis/consent, privacy filtering, export preparation and the manual sharing
panel sources are unchanged from the baseline; their existing assertions passed
inside packages. No telemetry, credentials, automatic report saves, automatic
AI transmission or privilege escalation were added. AppImage retains existing
explicitly described scan traffic (limited ICMP and local Ollama queries);
Flatpak has no network permission. Build/download operations do not run during
ordinary launch. No host packages, services or global settings were modified.

Remaining gates: successful manual native/portal save-picker selection and
portal-granted destination writes; real capture/playback; successful SMART
hardware access under ordinary permissions; independent second desktop/session;
other CPU architectures; final publisher/URLs and application licensing. The
additional Fedora GUI run is a userspace compatibility result only. AppImage's
large complete-runtime bundle, host font configuration dependency and optional
FUSE requirement are documented in PACKAGING.md.
