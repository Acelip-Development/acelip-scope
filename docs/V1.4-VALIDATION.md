Bubblewrap worked outside the execution sandbox. Rootless user/process/network

root. Extraction does not preserve directory modes, ownership or capabilities.

[reproduction instructions](../scripts/validation/README.md).

Disposable setup only:

- Fedora: DNF installed Python, PyGObject, Pycairo, GTK4, libadwaita and fonts.
  The initial transaction failed on GStreamer file capabilities and a dbus
  helper's non-root ownership. `gobject-introspection` was also needed. Installing
  GStreamer with `--setopt=tsflags=nocaps` made the real GTK libraries usable.
  The dbus daemon remained uninstalled; a missing-session-bus GTK warning is
  expected. This image is not a fully configured Fedora desktop.
- Arch: `pacman -Syu --noconfirm --disable-sandbox python` inside Bubblewrap.
  The download subprocess sandbox was disabled only inside this disposable
  rootless image. Its setup hooks correctly skipped booted system managers.
- openSUSE: `zypper --non-interactive install --no-recommends python3` inside
  the image. Mirror 404s retried successfully; final setup exit status was zero.
- Debian: Python was already present in the selected official image; no setup
  packages were installed.

All setup changes are confined to `var/v14-environments/*/rootfs`. No Discord,
SMART utilities, drivers, permission rules or portal/audio configuration were
installed or changed on the actual host. No service was started/stopped/enabled
on the host. Rootless image setup can run image package scripts, with no host
service bus or devices exposed.

File differences are genuine command output, strongly affected by extraction
mode/ownership/link transformations and setup. They are not evidence that stock
distros are corrupt. Verification has a 20-second deadline and bounded output;
partial/truncated/permission cases cannot become a clean PASS. RPM verification
scripts are explicitly disabled. The safe options were checked against the
[RPM manual](https://rpm.org/docs/6.0.x/man/rpm.8); pacman's limited file/mtree
semantics against the [Arch manual](https://man.archlinux.org/man/pacman.8).

booted systemd/systemd-user behavior, audio playback, portals and capture.
Missing tools and hidden devices report UNAVAILABLE, absent running systemd
reports UNSUPPORTED, and services do not start. GUI is additionally skipped on
Debian, Arch and openSUSE. Container display/session identity remains unknown
rather than borrowing the host's GNOME identity.

An additional **explicitly injected empty-PATH Arch run** executed all scans and
exports successfully with `smartctl`, `sensors`, `wpctl`, `pactl`, `nmcli`,
